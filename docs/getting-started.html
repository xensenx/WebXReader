Getting Started

Everything you need to clone, run, build, test and ship WebXReader. The project has no environment variables, no secrets, and no backend — a Node install and the repository are enough.

Prerequisites

RequirementDetail
Node.js22.x — the CI workflow pins Node 22 (.github/workflows/firebase-hosting-production.yml). Any modern Node item ≥ 20 works locally; 22 is the tested baseline.
npmComes with Node. CI uses npm ci, so a regular install is fine for development.
A browser with IndexedDB + OPFS-grade APIsAny evergreen Chromium/Firefox/Safari. The app targets ES2022 JavaScript (vite.config.ts, build.target).
Optional: Python not requiredNo Python-based toolchain; the whole pipeline is npm-only.
NO ENV CONFIG NEEDED

There are no .env.* files, import.meta.env reads, or required API keys anywhere in the source. The Firebase project credentials used by CI are wired through GitHub's Workload Identity Federation with id-tokens, never repo secrets — see PWA & Deployment → CI/CD.

Install and run

git clone <your-fork-url> webxreader
cd webxreader
npm install        # or: npm ci (reproduces the lockfile exactly)

npm run dev        # Vite dev server, default http://localhost:5173

The dev server talks to src/ directly with native ES modules and HMR. Because index.html detects development hostnames (localhost, 127.0.0.1, ::1) and unregisters any existing service worker and purges webxreader-* caches, you get clean reloads without stale-PWA problems while developing.

Production build & preview

npm run build      # tsc -b (typecheck via project references) then vite build
npm run preview    # builds first (npm run build && vite preview) at http://localhost:4173 (strict port)

Build output goes to dist/. npm run preview serves it at port 4173 strictly (vite.config.ts sets preview.port = 4173, strictPort = true). Use preview mode to verify PWA behavior: on non-localhost origins the service worker will actually register and the install prompt becomes available.

What the build produces

vite.config.ts pins target: 'es2022', emits sourcemaps, aliases @ → ./src, and hand-splits vendor chunks via rollupOptions.output.manualChunks:

ChunkContainsWhy
vendor-epubepubjsLoaded lazily only when an EPUB reader opens
vendor-pdfpdfjs-distLoaded lazily only for PDF books
vendor-zipjszipLoaded when a CBZ is parsed, plus backup base64-free restore downloads
vendor-parsermarked, dompurifyMarkdown + sanitization on demand
vendor-iconslucide-reactIcon tree-shaking, avoids UI-code mixing
vendor-reactreact, react-dom, react-router-domStable framework layer, long-term caching

Tests

npm test                 # vitest run (one-shot, CI mode)
npm run test:watch       # vitest in watch mode
  • Runner: Vitest 5, configured inside vite.config.ts — globals: true, environment: 'jsdom', setupFiles: ['./src/test/setup.ts'], CSS modules classNameStrategy: 'non-scoped'.
  • IndexedDB: fake-indexeddb/auto gives the environment a real IndexedDB-compatible object store database so storage logic is tested end-to-end without a browser.
  • 12 suites cover storage, import, dedup, backup/restore, parsers, the format registry, library ordering + state, component rendering, and an XSS-regression suite. See Testing & Quality for a description of every file.

Lint

npm run lint             # oxlint

The project uses oxlint with repository-local config in .oxlintrc.json. There is no ESLint Prettier ESLint setup to fight — a single fast linter, no formatters configured (keep code style consistent manually with neighboring lines: 2-space TypeScript indentation, single quotes with semicolons, React function components with hooks).

Getting sample books to play with

  1. Run npm run dev and open http://localhost:5173.
  2. Click the import button (or drag files onto the empty-state dropzone) in the library.
  3. Drop any of fixtures/sample-novel.txt, sample-novel.md, sample-novel.html or sample-novel.pdf.
  4. Open one and confirm: a chapter list is auto-built, progress updates are debounced, and the position survives a reload.
  5. Try Settings → Export library backup, delete the book, and restore the JSON backup. The dedup + contentHash machinery will either skip the original entry or re-import it intact — see Import & Backup.
REMEMBER: DATA IS PER-BROWSER/PROFILE

Importing books in a private window, or a different browser profile, produces a different library — nothing is shared across profiles. Clearing site data or storage quota eviction (see Storage → Persistence) deletes your library, so keep a JSON backup if you care about the content.

TypeScript configuration

The repo uses a solution-style root tsconfig.json referencing two child configs. Useful notes before you add code:

  • tsconfig.app.json — target/lib ES2023, DOM, jsx: react-jsx, bundler resolution with allowImportingTsExtensions, verbatimModuleSyntax (use import type for type-only imports), noEmit (Vite emits), plus noUnusedLocals / noUnusedParameters — dead params will fail the build.
  • tsconfig.node.json — only covers vite.config.ts with module: nodenext and Node types.
  • Path alias @ → ./src works at compile and runtime; prefer it over relative ../../.. climbs in new code.
